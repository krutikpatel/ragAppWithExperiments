## What happened

The run died on its first rerank call, 61 documents in:

```
qwen/qwen3-reranker-8b via Fireworks: HTTP 402 on 61 documents:
{"error":{"message":"Insufficient credits. Add more using
https://openrouter.ai/settings/credits","code":402, ...}}
```

The OpenRouter account ran out of credit partway through the Axis 5 batch. EXP-0024
($0.234) and EXP-0025 ($0.448) had already spent $0.682 of the axis's budget, on top
of $1.63 of earlier Phase 2 spend.

402 is **not** in the retry set, which is correct: a credit exhaustion is not
transient and retrying it eight times with backoff would have wasted four minutes to
reach the same answer. The error was raised on first occurrence with the provider's
body intact, which is what made the cause obvious rather than mysterious (MIS-010).
The runner recorded the row VOID with the exception attached rather than dropping it.

`cost_actual_usd` is NULL: the provider refused the request, so there was no usage to
report. This is the one case where a VOID run's cost is genuinely zero rather than
merely small.

## Anomalies

- **Recorded `git_dirty=1`, and this one is the runner's own doing.** The tree was
  clean when the batch launched. EXP-0025, running first, appended its approval row to
  the cost-approvals log in `docs/DECISIONS.md` — a **tracked file** — so by the time
  EXP-0026 read git state the tree was dirty through no action of anyone's. See
  MIS-030: the "a run in flight owns the working tree" rule (MIS-027) cannot be
  satisfied by a batch of approved runs, because the runner dirties the tree itself.
