# EXP-0038 — Abstention threshold sweep (reconstructed, not run)

- **Status:** VALID — **no run was made.** Reconstructed exactly from two recorded runs.
- **Date:** 2026-09-25
- **Source runs:** `run_20260913_205058_dc03` (EXP-0006, dev Tier 2) and
  `run_20260913_060733_6a9b` (EXP-0007, unanswerable Tier 2)
- **Cost:** **$0.00**
- **Detector:** `refusal-lexical-v3` (MIS-038), applied to the stored answers

## Question
How does the false-answer rate on `unanswerable` trade against the false-refusal rate on
`dev` as a confidence threshold moves? P2-14 is explicit that **the curve is the finding
and a single operating point is not**.

## Why no run was made
The mechanism swept is the cheapest available: **abstain before generating when the top
retrieval score is below a threshold.** No LLM call, no added latency — and the decision
is a pure function of numbers already in the results store. Per-question retrieval
scores and generated answers are recorded on every Tier 2 row, so every threshold is
evaluable exactly. Spending an experiment slot to re-measure numbers already on disk
would be theatre; DEC-061 made the same argument for the top-k sweep.

Reproducible from `rag/eval/abstention.py`, which is tested against these two runs.

## Definitions
- **false answer** — the system returned an answer to a question the corpus cannot
  answer. Over the whole 45-question `unanswerable` split.
- **false refusal** — the system declined a question it *could* have answered, so it is
  counted only over the 67 dev questions whose gold document actually reached the
  generator. Refusing when retrieval failed is correct behaviour, not a false refusal
  (MIS-012).
- The threshold **composes with** the generator's own refusals: the system answers only
  when `top1 >= T` **and** the generator chose to answer.

## Does the signal separate at all?
Before the curve is worth reading: the top-1 retrieval score on answerable dev questions
averages **0.7325** against **0.6472** on unanswerable ones, and ranks them at
**AUC 0.7116**. That is a usable signal and not a strong one — which is what the shape of
the curve below then shows.

## The curve

|---|---|---|---|
| **0.000** (no threshold) | **0.2667** | **0.0299** | 0.930 |
| 0.550 | 0.1556 | 0.0299 | 0.930 |
| **0.575** | **0.1333** | **0.0299** | **0.930** |
| 0.600 | 0.1333 | 0.0597 | 0.890 |
| 0.625 | 0.0667 | 0.1045 | 0.850 |
| 0.650 | 0.0444 | 0.1343 | 0.800 |
| 0.675 | 0.0444 | 0.2388 | 0.690 |
| 0.700 | 0.0444 | 0.3134 | 0.600 |
| 0.725 | 0.0222 | 0.4328 | 0.510 |
| 0.750 | **0.0000** | 0.5224 | 0.430 |
| 0.800 | 0.0000 | 0.7463 | 0.190 |

## Observations

**There is a free move, and it is the only one in the phase.** At **T = 0.575** the
false-answer rate falls from 0.2667 to **0.1333 — halved — while the false-refusal rate
is unchanged at 0.0299 and not one dev question stops being answered.** Every unanswerable
question it newly declines scored below every answerable question's top-1 score. Nothing
was traded.

**Past 0.575 it becomes a real trade, and a steep one.** Halving false answers again
(0.1333 → 0.0667 at T = 0.625) costs a **3.5x rise in false refusals** (0.0299 → 0.1045)
and 8 dev questions. Eliminating false answers entirely (T = 0.750) costs **52% false
refusals** — the system would decline more than half the questions it can actually
answer. The curve's knee is narrow and sits between 0.575 and 0.625.

**The absolute numbers are small and should be read that way.** "Halved" is 12 of 45
unanswerable questions becoming 6. The false-refusal denominator is 67. A curve drawn
from 45 and 67 questions has wide error bars that the table does not show.

## Anomalies
No threshold below 0.55 changes anything: every top-1 score in both splits exceeds 0.37,
so the interesting range is compressed into 0.55–0.75. That is a property of a cosine
similarity over a single-product corpus — nothing is ever *very* dissimilar to the query
— and it means the usable operating range is about 0.2 wide.

## The caveat that matters most
**The threshold is selected on the same data it is evaluated on.** Tuning on `dev` is
permitted and stated (CLAUDE.md §3), but `unanswerable` is being used here both to choose
the operating point and to report its performance, which makes 0.1333 optimistic. The
honest test is the held-out `test` split in P2-18, and this curve should be re-read there
before any operating point is trusted in production.

## Reproduce
```python
from rag.eval.abstention import sweep, format_curve
from rag.runner.store import ResultsStore
with ResultsStore() as s:
    print(format_curve(sweep(s.get_questions("run_20260913_205058_dc03"),
                             s.get_questions("run_20260913_060733_6a9b"),
                             [0.0, 0.55, 0.575, 0.6, 0.625, 0.65, 0.7, 0.75])))
```
