## What happened

The `dev_large` run passed the cost gate ($0.033 estimated) and began the 196k-row
index build (3,065 embedding calls at batch 64). About 42 minutes in, DeepInfra
returned **HTTP 429 Too Many Requests**; the embedder's retry policy (4 attempts, 2 / 4 / 8 s
backoff) expired inside the rate-limit window and the build raised. The runner
recorded the row VOID with the error. The `dev` run that followed found no index on
disk, started its own build, and hit the same 429 at once. The partially built
embeddings were not saved (the index is written whole at the end), so the spend on
the first ~40 minutes of calls is lost; the row's actual cost is not recorded
because the retriever never finished constructing.

Root cause, fix and prevention rule: **MIS-024**.
